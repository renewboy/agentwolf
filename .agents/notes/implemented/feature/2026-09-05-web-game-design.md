# Agent Note: 民俗悬疑桌游界面

Status: implemented

## Problem

Web 面向组局和观战，需要以玩家、牌组、发言和局势建立可读的产品层级，同时支持桌面与手机。
内容浏览、配置编辑、异常恢复与开发者轨迹具有不同的交互职责。

## Decision

采用民俗悬疑与实体桌游的视觉语言：炭黑台面、纸色文字、朱砂关键操作、木刻图形与通用控件
材质。游戏页的功能图标由同一木刻图集通过 GameIcon 提供，涵盖导航、编辑、保存、设置、声音、
观战和结算。图集与场景原图保存在 assets，运行时消费尺寸适配的 WebP。

人数与其他动态数值直接来自板型数据，由页面文字呈现。人数选择共享通用材质，适用于自定义
板型；图像资源不限定人数、身份数量或其他领域取值。

大厅突出开始和继续观战，并按状态筛选牌局。组局分为选择牌组和安排玩家，操作区持续显示
当前牌组与启动入口。创建后的启动重试复用同一牌局 ID，并锁定已保存配置。

板型和人设提供独立的阅读详情，进入编辑后才显示表单。Agent 主要配置聚焦工具和模型，高级
参数按需展开，工具接入使用具有焦点管理的 Modal。

观战以左右玩家列和中央消息气泡组织内容，玩家使用圆形头像，绑定 Character 时显示其肖像。暂停提供非模态恢复操作，技术详情
折叠展示。手机保留席位访问、完整操作和发言阅读。所有游戏事实继续消费 server projection，
切换视角时保护完整旧投影。

CSS 按 foundation、共用组件、页面、match、trajectory 和 simulation 维护。模块拥有自己的媒体
查询。轨迹与游戏共享顶部与控件材质，并保留类型颜色、记录选择、虚拟滚动和审计语义。

## Alternatives considered

- 仅调整颜色无法同时建立浏览详情、编辑流程和稳定的操作层级。
- 将动态数值绘制为专用图片，会使素材与领域取值发生不必要的耦合。
- 替换实时状态和隐私控制没有必要；呈现组件继续使用已有的 Core 与投影契约。

## Consequences

素材、图标和样式属于产品侧，不进入 Core、游戏规则或持久事件。页面与样式按实际职责维护，
视觉变更不要求修改 server 的游戏事实。共享控件的颜色、字体、边框和状态由组件样式统一维护，页面负责布局。

## Verification

`pnpm check` 验证类型、静态边界、格式、覆盖率与构建；`pnpm test:e2e` 验证配置、组局、视角、
声音、独立滚动、恢复、赛后和轨迹。人数覆盖包括自定义八人板型的选择、席位与创建请求。
浏览器视觉复核同时检查桌面与手机的字体、素材、控件、滚动和操作可达性。
