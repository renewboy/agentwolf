# AgentWolf 架构文档模板

本文是架构写作的决策模板。它规定文档必须回答的问题、可按需采用的章节和研发制图选择，不规定
固定标题或固定篇幅。正式文档应按目标读者和职责域裁剪，并遵循仓库的当前态规则。

## 文档定位

开篇用一至两段说明：

- 文档描述的系统或职责域；
- 目标读者需要据此理解或完成什么工作；
- 文档覆盖的运行边界，以及哪些精确行为由其他架构文档、README、Schema、代码或测试负责。

不要以目录清单、历史背景或“本文将介绍”式长序言代替定位。

## 必须回答的架构问题

### 目标与约束

说明当前设计需要同时满足的能力和约束，例如确定性、事件重放、隐藏信息、长驻 Agent Session、
流式呈现、可恢复性或本地部署边界。只保留能够解释当前结构的约束。

### 系统边界

定义调用方、系统内部、外部 Agent 进程、持久化和浏览器边界。系统级文档应有一张上下文图；专项
文档可以用一段边界说明替代。

涉及隐藏信息时，明确原始状态、可见事实和最终消费方之间的 trust boundary。浏览器本地隐藏、
Prompt 模板条件或 UI 状态都不能被描述成授权机制。

### 组件职责与依赖方向

按稳定职责组织组件，而不是按目录逐项介绍。每个主要组件至少说明：

- 它拥有的决策或状态；
- 它接收和产出的契约；
- 它依赖谁，以及谁可以依赖它；
- 它明确不负责什么，但只在该否定构成当前重要边界时说明。

组件较多时使用表格；依赖方向复杂时增加组件图。

### 关键数据流与控制流

选择最能解释系统行为的一至三个场景，描述入口、校验与归一化、编排、执行、持久化、投影及返回。
流程需要说明：

- 哪一层决定下一步；
- append-only 事件、Session 流和浏览器消息如何汇合；
- 并行阶段何时冻结、何时揭晓；
- 失败在哪一层终止，恢复从哪个持久边界继续。

### 状态、所有权与生命周期

列出跨回合存活的状态和请求级临时状态，说明创建、读取、提交、失效和释放的唯一所有者。Match、
Ruleset lock、事件日志、Player Session、delivery cursor、pending action、WebSocket、播放队列或轨迹
存在时，必须说明暂停、恢复、关闭和删除的影响范围。

### 扩展边界与不变量

说明新增 Role、Ruleset plugin、Prompt bundle、ACP Provider、投影字段或浏览器呈现时应接入的稳定
扩展点，以及不得反转的依赖、不得绕过的状态所有者和必须保持的隐私边界。精确实现步骤链接到
Package README 或开发 Skill。

### 故障与可观测性

说明输入拒绝、规则非法、Session 传输不确定、进程退出、恢复失败、投影失败和客户端断线等架构级
故障如何跨边界传播。列出研发人员真正用于判断系统状态的领域事件、Match/Session 状态、delivery
台账、trajectory、错误 DTO 或浏览器连接状态。

### 深入阅读

链接承担精确事实的专项架构、Package README、Schema、生成参考、开发 Skill 和测试策略。导航用于
承接细节，不能成为文档主体。

## AgentWolf 专项视角

专项文档应优先回答与自身职责域相关的问题：

| 职责域          | 需要讲清的设计关系                                                    | 常用图表                             |
| --------------- | --------------------------------------------------------------------- | ------------------------------------ |
| 游戏运行时      | Ruleset 组合、phase 边界、action 校验、effect 结算、事件归约与 replay | 组件图、action 时序、结算流程        |
| Prompt 与上下文 | plugin 语义所有权、bundle 校验、可见事实投影、foundation/增量 Prompt  | 数据流图、Prompt 时序、信任边界图    |
| ACP Session     | 进程与逻辑 Session 分离、绑定、delivery、动作持久化与精确恢复         | 生命周期图、回合时序、恢复状态图     |
| 信息同步        | 事件/phase 可见性、barrier、流式发言、播报门控、重连                  | 投影管线、barrier 时序、播报时序     |
| Match 生命周期  | 目录到快照、运行时恢复、SQLite 所有权、删除、赛后状态机               | 生命周期图、持久化关系图、赛后状态图 |
| 轨迹            | ACP 回合采集、脱敏、分页、实时 delta、玩家诊断与语义审计              | 数据管线图、审计流程、状态所有权表   |
| 确定性仿真      | Match capture、规范化、candidate、双 runner、fixture 批准             | 采集流程、评审状态图、runner 对照图  |
| Web 客户端      | DTO 校验、远端/本地状态分工、视图切换、speech/motion 副作用           | 组件图、实时连接状态图、呈现数据流   |

这些视角用于选择设计问题，不要求每份文档包含表中所有图。

## 条件章节

只在对当前职责域确有解释价值时加入：

- 并发模型与 barrier；
- 安全、鉴权或隐私边界；
- 持久化格式与恢复机制；
- 部署与进程拓扑；
- 性能预算与容量模型；
- 浏览器兼容与降级行为。

未落地能力不得以架构章节或虚线组件进入当前态文档。

## 图表选择

| 需要解释的问题               | 推荐图表       | 图中必须出现                                          |
| ---------------------------- | -------------- | ----------------------------------------------------- |
| 谁在系统内外、调用从哪里进入 | 系统上下文图   | 浏览器、server、Agent 进程、持久化、主要协议          |
| 哪些组件协作、依赖方向如何   | 组件关系图     | 稳定职责、单向依赖、信任或 IO 边界                    |
| 一次 Match 回合如何完成      | 时序图         | Prompt、Agent、MCP action、持久化、engine、projection |
| 配置如何变成可执行 Match     | 流程图         | 目录输入、校验、不可变快照、Ruleset、runtime          |
| 状态如何暂停、恢复或结束     | 状态图         | 状态、触发动作、失败、恢复和终局路径                  |
| 隐藏事实如何到达消费者       | 数据流图       | 原始状态、visibility filter、DTO/Prompt、消费方       |
| 并行动作何时可见             | barrier 时序图 | 冻结序列、并行收集、密封动作、确定性提交              |

图表要求：

- 使用 Mermaid，并保持节点标签简短；
- 一张图只突出一个问题，避免把所有类放进同一张图；
- 图前说明读图目的，图后解释关键边界；
- 图中关系必须能在当前源码、Schema、配置或测试中验证；
- 不使用目录树、文件列表或类继承树替代架构关系。

## 建议结构

系统级文档通常按以下顺序组织：

1. 文档定位；
2. 设计目标与约束；
3. 系统上下文；
4. 组件职责与依赖；
5. 核心运行链路；
6. 状态和生命周期；
7. 故障、可观测性与扩展边界；
8. 架构不变量与深入阅读。

专项文档可以合并相邻部分，并把重点放在本职责域独有的协作、状态或数据转换上。

## 粒度与篇幅

- 系统架构讲清跨模块结构和端到端行为，不重复专项机制。
- 专项架构通常深入一层；函数签名、完整字段表、文件级索引和测试枚举由其他所有者承担。
- 代码片段只用于解释无法用契约描述的关键形态，不能复制实现。
- 表格用于稳定映射，正文用于解释设计关系，图表用于呈现结构、时序或状态。
- 每份架构 Markdown 以 500 行为硬上限；不要为接近上限而填充内容。

## 出稿检查

- 读者能否在不浏览目录树的情况下复述系统边界和核心运行链路？
- 每个主要状态是否有唯一所有者和明确生命周期？
- 每张图是否比同等长度的文字更清楚，并与正文术语一致？
- 是否把精确行为留给真实所有者，没有复制易漂移的字段或清单？
- 是否只描述当前实现，没有混入旧方案、迁移过程、候选设计或未来计划？
- 是否满足链接、中文、500 行和 `pnpm check:docs` 约束？
