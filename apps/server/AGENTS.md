# AgentWolf server guide

See [the root AGENTS.md](../../AGENTS.md) for repo-wide conventions. These instructions apply to `apps/server`.

Read [the architecture](../../docs/architecture.md) before changing ownership or dependency direction, [information synchronization](../../docs/information-sync.md) before changing projection, delivery, barriers, or recovery, and [testing and acceptance](../../docs/testing.md) before changing server tests or fixtures.

## Ownership

- The server composes Fastify, SQLite, the game engine, ACP sessions, MCP actions, and live projections. Deterministic game rules stay in `packages/game-engine`, wire schemas and DTOs stay in `packages/contracts`, model-facing text stays in `packages/assets`, and generic ACP process lifecycle stays in `packages/acp`.
- `app.ts` owns HTTP and WebSocket assembly, `repository.ts` owns durable SQLite access, `match-runtime.ts` owns live orchestration, `projector.ts` owns visibility-safe views, and `mcp.ts` owns player-bound structured action transport. Keep new behavior with the narrowest existing owner.
- `ruleset-catalog.ts` is the server composition root for installed Rulesets.
  `prompt-registry.ts` adapts each resolved Ruleset's semantic contribution records into one cached
  assets-owned Prompt bundle registry. Board catalog, Match creation and restore, runtime Prompt
  rendering, trajectory audit, and simulation use the same resolved Ruleset and verify schema-two
  fingerprints.
- `player-session-repository.ts` owns durable per-seat ACP Session bindings and accepted-action recovery state. `player-runtime.ts` owns one logical Session's create/resume, delivery cursor, continuation, and connection state.
- `postgame-review-repository.ts` owns durable review sheets, aggregates, reflections, and review
  attempts. `postgame-review-coordinator.ts` owns the countdown, same-Session review turns,
  per-Session public-history catch-up from the regular acknowledged cursor, sequential reflections,
  and terminal close without advancing that cursor or adding postgame records to the game event log.
- `character-catalog.ts` owns built-in/custom Character resolution, immutable snapshots, copy/edit/delete policy, and managed portrait files. Character persistence remains separate from game-engine state and events.
- `database-schema.ts` owns schema creation and migration, `trajectory.ts` owns capture and pre-persistence redaction, `trajectory-service.ts` owns Match-scoped reads and live deltas, and `trajectory-audit.ts` owns reconstruction checks.
- `simulation-service.ts` owns sanitized Match capture and candidate storage; simulation runner,
  orchestration, and Session-replay modules own deterministic offline execution and invariants.
  `simulation-workflow.ts` owns shared CLI and browser review and approval. Approved simulation
  fixtures live only under `tests/fixtures/simulations`.
- New REST or WebSocket fields start in `packages/contracts` schemas and receive route-level integration coverage. SQLite changes include a forward migration and coverage in `tests/migration.test.ts`.
- Do not hand-edit `dist/`; it is generated by the package build.

## Verification

- Keep server unit and integration coverage under `apps/server/tests`; use in-memory repositories and fake ACP processes unless the test is explicitly under `tests/live`.
- Run focused tests with `pnpm exec vitest run --config vitest.config.ts apps/server/tests/<name>.test.ts` and server type checking with `pnpm --filter @agentwolf/server typecheck`.
- Run the root gates required by the root guide for cross-package, persistence, protocol, or user-visible changes.
