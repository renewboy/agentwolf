# AgentWolf server guide

See [the root AGENTS.md](../../AGENTS.md) for repository-wide conventions. These instructions apply
to `apps/server`; [README.md](README.md) owns the package-local contract and ownership map.

Read only the architecture module touched by the change: [Match lifecycle](../../docs/architecture/match-lifecycle.md),
[ACP Session runtime](../../docs/architecture/acp-session-runtime.md),
[information synchronization](../../docs/architecture/information-synchronization.md), or
[trajectory and simulation](../../docs/architecture/trajectory-and-simulation.md). Read
[testing](../../docs/testing.md) before changing test infrastructure or fixture policy.

## Boundaries

- Keep deterministic rules in `packages/game-engine`, wire schemas in `packages/contracts`, generic
  ACP process behavior in `packages/acp`, and model/UI presentation in `packages/assets`.
- Keep new behavior with the narrowest existing server owner. New REST or WebSocket fields start in
  contracts schemas and receive route-level integration coverage.
- SQLite changes include a forward migration and migration coverage.
- Project every view through server-owned visibility filtering before serialization.
- Do not hand-edit `dist/`; it is generated by the package build.

## Verification

- Keep unit and integration coverage under `apps/server/tests`; use in-memory repositories and fake
  ACP processes unless the test is explicitly under `tests/live`.
- Run focused tests with `pnpm exec vitest run --config vitest.config.ts apps/server/tests/<name>.test.ts`
  and typecheck with `pnpm --filter @agentwolf/server typecheck`.
- Run root gates for cross-package, persistence, protocol, or user-visible changes.
